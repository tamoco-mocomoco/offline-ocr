## はじめに

[Chrome拡張「オフラインOCR」](https://chromewebstore.google.com/detail/offline-ocr/cfppiicaeemimcbodibggnnolckcpmpd) の v0.9.1 で、**ビューアーに「消しゴム」** を足しました。画像の中の **OCR したくない部分をなぞって消してから、OCR にかけられる** 機能です。

![請求書のはんこを消しゴムで消すと、OCR 結果から「承認」が消える](/images/10-01-before-after.png)

これまでのビューアーでできたのは「四角で範囲選択」「ゆがみ補正で選択（四隅を合わせて平面化）」「画像全体」の 3 つでした。どれも「**どこを読むか**」を指定する方法です。でも実際に使っていると、「**ここだけは読んでほしくない**」と言いたい場面がけっこうあります。四角で囲もうとしても、読みたい文字のすぐ隣に余計なものがあると、うまく囲めません。

消しゴムはその逆側からのアプローチです。読ませたくないものを先に消しておけば、あとは「画像全体をOCR」するだけで済みます。

## こんなときに使える

実際に「これは困るな」と思った場面を挙げてみます。

### 1. 請求書・申込書の「はんこ」まで読まれてしまう

冒頭の画像がまさにこれです。請求書の発行元の横に押された「承認」の印影まで文字として読まれて、`オフラインOCR開発室	承認` のように結果に混ざります。はんこは文字の形をしているので、OCR からすると読めて当然です。はんこの部分だけを消しておけば、結果は本文だけになります。

### 2. 手書きのメモ・赤ペン・チェックマーク

印刷した資料に書き込んだメモや、赤ペンの丸・チェックマークは、意味のない文字や記号として結果に紛れ込みがちです。書き込みの部分だけなぞって消せば、印刷された文字だけを読めます。

### 3. スクリーンショットのアイコンや画像

Web ページのスクリーンショットを `Ctrl+V` で貼って OCR すると、アイコンやロゴ、写真の中の文字まで拾ってしまうことがあります。本文のすぐ隣にあって四角で避けられないときは、そこだけ消すのが早いです。

### 4. ヘッダー・フッター・ページ番号

PDF のページを OCR すると、毎ページ同じ社名やページ番号が結果に混ざります。消しゴムで消した内容は **PDF のページごとに覚えておく** ので、ページを行き来しても消えません。

### 5. 段組みや回り込みで、四角く囲めない範囲

2 段組の片方だけ読みたいけど、間に図が挟まっている。図の周りを本文が L 字に回り込んでいる。こういう「四角では表せない範囲」は、範囲選択だけではどうにもなりませんでした。読みたくない側を消してから全体を OCR すれば、残った部分をそのまま読めます。

### 6. 漫画の擬音や描き文字

漫画のコマを OCR すると、台詞と一緒に背景の「ドドド」のような描き文字まで拾うことがあります。セリフだけ欲しいときは、描き文字を消してから読むと結果がすっきりします。

## 使い方

1. ビューアーで画像（または PDF）を開く
2. ツールバーの **「消しゴム」** を押す
3. **太さ**（細 / 中 / 太）を選んで、消したい部分をなぞる
4. 間違えたら **「元に戻す」（Ctrl+Z）**、全部やり直すなら **「すべて戻す」**
5. Esc で消しゴムを終えて、いつも通り「画像全体をOCR」や「範囲選択」をする（消した内容は残る）

![消しゴムの UI。太さ・元に戻す・すべて戻すがツールバーに出て、カーソルがブラシの大きさの丸になる](/images/10-02-viewer-ui.png)

消した結果は「範囲選択」「ゆがみ補正で選択」「画像全体をOCR」のどれにも、そのまま反映されます。

## 仕組みと、こだわったところ

### 消した跡は「周りの色」で塗る

一番悩んだのは「消した跡を何色で塗るか」でした。

単純に考えると白で塗ればよさそうです。でも、オフラインOCR が読む画像は白い紙だけではありません。ダークモードの画面のスクリーンショットもあれば、クリーム色の紙や、机の上で撮った写真もあります。暗い背景を白で塗ると、**背景とまったく違う色のかたまりと、その輪郭** が残ります。

![暗い背景の 2 行目を消したときの比較。白で塗ると白いかたまりが残り、周りの色で塗ると背景に溶け込む](/images/10-03-fill-color.png)

正直に書くと、この例では白で塗っても OCR の結果は同じ（どちらも `残しておく行`）でした。それでも、文字を探す側（DEIM）からすると、背景と違う色のかたまりは余計な手がかりにしかならないので、わざわざ作る理由はありません。オフラインOCR は以前から、選択範囲のパディングも白ではなく「隣接する色」で埋めてきたので、それと同じ考え方にしました。

塗る色は、**なぞり始めた位置のまわりで一番多い色** にしています。

- なぞり始めの点を中心に、ブラシの半径の 8 倍（最低 64px）四方の正方形を調べる
- 各色を RGB それぞれ 16 段階にまとめて数える（JPEG のノイズで背景が何色にも割れないように）
- 一番多かったグループの **平均の色** で塗る（グループの中央値ではなく平均なので、真っ白な紙は真っ白で塗れる）

文字はふつう背景より面積が小さいので、まわりで一番多い色はたいてい背景の色になります。画像全体の端の色を使う方法もありますが、それだと「机の上で撮った紙」では机の色で塗ってしまいます。

ちなみに途中で「マスキング（黒で塗りつぶす）」という案も検討しました。何が起きるかわかりやすく、墨消しのように見た目もはっきりします。でも最終的に、名前は「消しゴム」のほうが伝わりやすく、周りの色で塗るほうが跡も目立たないので、消しゴムのままにしました。

### ブラシの太さは、画面上で一定にする

大きな画像はウィンドウに合わせて縮小して表示しています。ブラシの半径を画像のピクセルで固定すると、縮小表示のときに細すぎたり太すぎたりします。そこで、太さは**画面上の大きさ**（細 12px / 中 28px / 太 56px の直径）で決めて、表示倍率をかけて画像のピクセルに直しています。カーソルもその大きさの丸にしているので、どこまで消えるかが見たままわかります。

### 「元に戻す」は描き直しで実現する

元に戻すために、毎回画像をまるごと保存しておく方法もあります。でも 4000×3000 の写真だと、1 回分で約 48MB（4000 × 3000 × RGBA 4 バイト）になります。

そこで、**なぞった軌跡（点の列・太さ・色）だけを記録** しておき、元に戻すときは「元の画像を描き直して、残りの軌跡をもう一度なぞる」ようにしました。軌跡のデータはとても小さいので、何回消しても軽いままです。PDF ではこの記録をページごとに持っています。

## 表示用と OCR 用のキャンバスを分けたら、バグが見つかった

消しゴムを作るには、「消した結果の画像」を、画面に表示しているキャンバスとは別に持つ必要があります。画面のキャンバスは、選択枠を描いたり、Esc で消したりするたびに元の画像から描き直しているからです。

そこで既存のコードを読み直していて気づいたのが、**範囲選択と「ゆがみ補正で選択」で、画面に描いた選択枠ごと OCR に渡していた** というバグです。画面のキャンバスには青い半透明の塗り・点線・四隅のハンドルが描いてあるのに、OCR 用の画像もそこから切り抜いていました。

選択範囲の端にある点線は、そのあとのパディングで外側に引き伸ばされ、縞模様の枠になります。大きな文字なら結果は変わりませんでしたが、**小さい文字をぴったり囲むと結果が崩れていました**。

![修正前に範囲選択で OCR に渡っていた画像と、修正後の画像。Settings が「群の中には、その」になっていた](/images/10-04-overlay-bug.png)

| 選択した文字 | 修正前（v0.9.0 まで） | 修正後（v0.9.1） |
|---|---|---|
| `Settings`（14px） | `群の中には、その` | `Settings` |
| `cfa8b33`（18px） | `$1` | `cfarb3` |

どちらもビルドした拡張機能そのもので、上下左右 2px の余白でぴったり選択したときの実際の結果です（`cfa8b33` が完全に読めないのは小さい文字の認識の限界で、このバグとは別の話です）。

修正は、消しゴムのために用意した「OCR 用の画像」（`OffscreenCanvas`）から、OCR・ゆがみ補正・補正後プレビューのすべてを取るようにするだけでした。消しゴムの土台と、バグ修正の中身がまったく同じだったわけです。

### バグをテストで再現する

このバグは、既存の E2E テストでは見つかりませんでした。E2E はビューアーを経由せず、OCR エンジンを直接呼んでいたからです。

そこで、**本物の `viewer.html` を Vite の開発サーバーで開くテスト**を足しました。ビューアーが使う `chrome.*` の API は、受け取ったメッセージを記録するだけの差し替え版にしています。

```ts:test/e2e/helpers/viewer.ts
await page.addInitScript(() => {
  const sent: unknown[] = [];
  (window as any).__sent = sent;
  Object.defineProperty(window, "chrome", {
    configurable: true,
    writable: true,
    value: {
      i18n: { getMessage: () => "" },
      tabs: { getCurrent: async () => ({ id: 1 }) },
      runtime: {
        sendMessage: async (m: unknown) => { sent.push(m); },
        getContexts: async () => [{}], // offscreen document はもうある体で
        onMessage: { addListener: () => {} },
      },
      // storage なども同様に空の実装
    },
  });
});
```

これで、ビューアーが OCR に送った `run-ocr` メッセージから、**OCR に実際に渡る画像** を取り出せます。テスト画像を白黒だけで作っておけば、「色の付いた画素が 1 つでもあれば、それは青い選択枠が混ざったもの」と判定できます。修正前は範囲選択で 99.3% の画素に色が付いていて、テストがきちんと失敗することを確かめてから直しました。

消しゴムのほうも、同じ仕組みで「消した部分が背景の色で埋まっている」「OCR 結果から消した行がなくなる」「Ctrl+Z で戻る」などをテストしています。

| Suite | 件数 | 今回の追加 |
|---|---|---|
| vitest | 202 pass | 消しゴムの計算部分 19 ケース |
| Playwright E2E | 32 pass | ビューアーの OCR 入力 4 / 消しゴム 4 / PDF 2 |

## 画像エディタとの棲み分けと、この先

ビューアーは、範囲選択、ゆがみ補正、そして消しゴムと、少しずつ「画像を触る」機能が増えてきました。キャンバスの上でできることは、まだまだありそうだと感じています。

一方で、「それなら Photoshop などの画像エディタで整えてから読めばいいのでは？」という考え方もあります。実際、それで困るわけではありません。ただ個人的には、オフラインOCR のビューアーは画像エディタとは**目的が違う**と思っています。

- **画像エディタ**は、きれいな画像を**作る**ための道具
- **オフラインOCR のビューアー**は、画像から文字を**読む**ための道具

なので、ビューアーに入れる機能は「画像を整えるための編集」ではなく、「**文字を読ませるための前処理**」に絞りたいと考えています。具体的には、こんな線引きです。

- **編集した画像は保存しない。** 消しゴムもゆがみ補正も、OCR に渡すためだけのもので、元の画像は変えない
- **機能は目的で名付けて、設定を増やさない。** 「ゆがみ補正」「消しゴム」のように何のための機能かがわかる名前にして、選べるのは太さ 3 段階くらいにとどめる
- **自動でやれるところは自動、確実さが要るところは人の手で。** 塗る色は自動で決め、どこを消すか・四隅をどこに合わせるかは人が決める
- **レイヤーや高度な選択ツールは入れない。** そこまで必要なら、画像エディタのほうが向いている
- **別のアプリとの往復をなくす。** 画像エディタで前処理して、保存して、開き直す、という手間がなくなるのが、ビューアーでやる一番の価値だと思っています。もちろん、すべてオフラインで完結するのは変わりません

この線引きの中でも、まだできることはありそうです。たとえば、

- 赤いはんこや赤ペンを、**色で**まとめて消す
- 薄いコピーや裏写りに効く、明るさ・コントラストの調整
- 消した範囲を、PDF の**全ページ**に同じように当てる（ヘッダーやフッター向け）
- 複数の範囲を選んで、順番にまとめて OCR する

などです。どれもまだアイデアの段階ですが、「Photoshop の代わり」を目指すのではなく、**OCR のためのキャンバス** として少しずつ育てていきたいと思っています。

## まとめ

- v0.9.1 で、ビューアーに **消しゴム** を追加。はんこ・手書きのメモ・アイコン・ページ番号・描き文字など、OCR したくない部分を消してから読める
- 四角では囲めない範囲も、「消してから全体を OCR」で読めるようになった
- 消した跡は **なぞり始めた位置のまわりで一番多い色** で塗る。暗い背景や色の付いた紙でも浮かない
- ブラシの太さは画面上で一定。元に戻すは軌跡の描き直しで軽く
- 表示用と OCR 用のキャンバスを分けたら、**選択枠が OCR 入力に写り込むバグ** が見つかり、一緒に直った
- ビューアーは画像エディタではなく、**文字を読ませるための前処理の場所**として育てていく
