## はじめに

[オフラインOCR](https://chromewebstore.google.com/detail/offline-ocr/cfppiicaeemimcbodibggnnolckcpmpd) という Chrome拡張を作って Chrome Web Store に出しました。範囲をドラッグするだけで画面上のテキストを読み取り、クリップボードにコピーする。通信ゼロで動く、ブラウザ完結のOCRです。

詳細は[前回の記事](https://zenn.dev/lecto/articles/offline-ocr-introduction)で紹介しています。

リリース後、自分で毎日使っていると、初版では気づかなかった小さな引っ掛かりが次々と見えてきました。**「動く」と「使い心地がいい」は別物**だな、と改めて実感した数週間でした。

この記事では、v0.2.0 から v0.5.0 までで対応した内容を、「なぜそれを直したくなったか」と一緒に書き残しておきます。コードは GitHub に出ています。

https://github.com/tamoco-mocomoco/offline-ocr

## v0.2.0 — タイトな範囲選択でも OCR を動かしたい

リリース直後に最初に気になったのが、**短いテキストを狭くピッタリ囲んで選択したときに、何も認識されない** という挙動でした。

OCRエンジン側（DEIM）はテキスト領域の検出に「周囲の余白」をある程度前提にしています。文字ギリギリで囲むと、検出器が「これは文字じゃない」と判断してしまう。

ユーザー視点だと、ボタンの文字や1行のリンクをコピーしたいときほどタイトに囲みたくなるので、「気軽に使う」用途と相性が悪い。

対応はシンプルで、**クロップした画像の四辺に、隣接色のパディングを足してから検出器に渡す** ようにしました。

- 短辺の30%（最大50px）を、端ピクセルの引き伸ばしで追加
- 白でも黒でも、その背景に馴染む色になるので暗背景でも検出が安定する

最初は白で固定していたのですが、暗いテーマのページでテストしたら検出失敗が増えたので「隣接色」方式に切り替えました。地味ですが、これだけで「狭い選択でも普通に動く」体感になりました。

合わせてこのバージョンから、**onnxruntime-node + sharp を使った OCR 統合テスト** も追加しています。検出/認識ロジックを触るときに、テスト画像をsharpのSVGから動的生成して、実モデルで end-to-end の挙動を回す。CIで回せるようにしておくと、後のリファクタが怖くなくなりました。

## v0.3.0 — ローカル画像にもちゃんと対応したい

しばらく使っていると、「**Web ページ上のテキストだけじゃなくて、手元の画像ファイルや PDF の画像化も OCR したい**」という当然の欲求が出てきます。

Chrome拡張で `file://` を扱おうとすると、ユーザーに `chrome://extensions/` から「ファイルの URL へのアクセスを許可する」を ON にしてもらう必要があります。これ、説明しても割と面倒だし、そもそも気づかれない。

そこで、**拡張機能内に画像ビューアーページを持たせる** 方向に振りました。

- ポップアップから「画像を開く」「クリップボードの画像を開く」を選んで起動
- ファイル選択 / ドラッグ&ドロップ / `Ctrl+V` 貼り付け、どれでも受け取れる
- ビューアー内で「範囲選択を開始」または「画像全体を OCR」を選択

ビューアーは拡張機能のオリジン（`chrome-extension://...`）で開くので、`file://` 権限なしでローカル画像をそのまま扱えます。

このタイミングで内部実装もちょっと整理しました。

- `src/shared/settings.ts` — 設定の load/save を一箇所に
- `src/shared/cleaning.ts` — クリーニングルールの型と適用ロジック

ビューアー、オプションページ、Content Script でそれぞれ独自にlocalStorageを触っていたのを、共通モジュールに寄せた感じです。

ただし Content Script は ES モジュール import が使えないので、そこだけは従来通りインラインで持たせています。

副次的に、**ポップアップから OCR を起動した時のアラートが拡張ページと通常ページで二重に出る** バグも踏んだので、メッセージ送信を分岐させて解決しました。手元のページ種別で挙動が変わる Chrome拡張あるあるです。

## v0.4.0 — ページ上の画像も「拡大してから」選びたい

v0.3.0 でローカル画像対応はできたのですが、別の場面で詰まりました。

**Web ページ上に小さく表示されている画像のテキストを OCR したいとき**、ページ上の表示サイズが小さすぎて範囲選択しづらい。あるいは画像の上に透明な要素が乗っていて、そもそもうまくドラッグできない。

「右クリックして名前を付けて保存 → ビューアーで開く」は手数が多い。**右クリックから一発でビューアーに送り込めればいい** ということで、画像のコンテキストメニューに「ビューアーで画像を開く」を追加しました。

実装としては `contextMenus.create` に `contexts: ["image"]` を指定して、選ばれた画像の `srcUrl` をビューアーページに渡すだけ。地味な追加機能ですが、トレカ画像など「小さく表示されている画像」を扱うときの体験が一気に楽になりました。

## v0.5.0 — 表のOCR、置換のエスケープ、青枠混入バグ、デバッグモード

ここが一番、自分の使い方が変わって発見が増えたバージョンです。

### 表・レシートをタブ区切りで出す

請求書やレシートをOCRしてExcelに貼ったとき、**同じ行に並んでいるセルが改行で繋がってしまって、列がバラバラに分解される** のがしばらく気になっていました。

検出側は同じ行に複数のテキスト領域があることはわかっているので、これを `\t` で連結するように変更。すると、ExcelやGoogle Sheetsに貼り付けたときに自然と列が分かれるようになります。

地味ですが、「OCR してそのまま表計算に流す」というワークフローのときの摩擦が一気に減りました。

### クリーニングルールでエスケープ記法を使えるように

このアプリには、認識結果を正規表現で整形できる「クリーニングルール」があります（オプションページで編集）。例えば数字の `,` を消したり、改行を整えたり。

ところが、置換文字列に `\t` と書いても、**そのまま「バックスラッシュ + t」として扱われる** のでタブを入れられない、というのが地味に困りました。タブ区切り出力に合わせてセル区切りをカスタマイズしたい人向けの抜け道がないわけです。

`applyCleaningRules` の中で `\t` `\n` `\r` `\\` `\0` をエスケープ解釈するように変更しました。`$1` などの後方参照は従来通り動きます。

### 青い選択枠が OCR画像に混入していたバグ

これがちょっと衝撃でした。

範囲選択UIで描いている青い半透明の矩形が、`captureVisibleTab` で取った画像にうっすら写り込んでいる。**v0.2.0 で入れた隣接色パディングが、端ピクセルとして「青み」を引き伸ばしてしまい**、結果として検出失敗を引き起こすケースがそこそこありました。

挙動的には、

1. ユーザーがドラッグで選択枠を描く
2. JS で「選択枠を消すリクエスト」を出す
3. 直後に `captureVisibleTab` を呼ぶ
4. ブラウザの再描画が間に合わず、青枠が残ったままキャプチャされる

という典型的な「再描画タイミング問題」でした。

選択枠を `display: none` にした後で `requestAnimationFrame` を1フレーム挟んでから `captureVisibleTab` を呼ぶようにしたら解消。デバッグモード（後述）で実際にOCRに渡される画像を確認しながら詰めたバグです。

### デバッグモード

「OCRに渡される直前の画像」が見えれば、上のような青枠混入もすぐ気づけたはず。

ということで、オプションページにデバッグモードのトグルを追加しました。ONにすると、

- 隣接色パディング込みのクロップ画像が保存される
- オプションページからその画像を確認できる

普段は OFF にしておけば容量も食わないし、何か怪しい時だけ ON にして検証できます。**自分のためのツールが、自分の使い込みの中から出てくる**のは個人開発の楽しいところです。

## おわりに

v0.1.0 から v0.5.0 までの対応を振り返ると、「機能を増やす」というより、**実際に使ったら気付いた摩擦を一つずつ削る** 作業がほとんどでした。

- タイトに選択しても動く
- ローカルの画像も普通に扱える
- ページ上の画像は右クリックで開ける
- 表は表のまま貼れる
- バグはデバッグモードで自分で追える

それぞれは小さな改善なのですが、合わせると「**気軽に使える**」の体感がかなり変わります。

今後も使い込みの中で気になったところは引き続き直していくつもりです。「こういう場面で使いたいんだけど動かない」「こうなってると嬉しい」みたいなものがあれば、ぜひ [GitHub Issues](https://github.com/tamoco-mocomoco/offline-ocr/issues) や Chrome Web Store のレビューで教えてください。要望ベースで対応していけたらと思っています。
